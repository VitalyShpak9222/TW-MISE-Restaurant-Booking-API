# TW-MISE-Restaurant Booking API

REST API для онлайн-бронирования столов в ресторане. Сервис позволяет создать бронь, получить список броней с фильтром по дате, получить бронь по id и отменить бронь без физического удаления записи.

## Стек

- Python 3.11+
- FastAPI
- Pydantic v2
- SQLAlchemy 2.0 async
- SQLite
- pytest + httpx.AsyncClient
- Docker / docker-compose

## Локальный запуск

Linux:

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app
```

Windows:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app
```

API доступно на `http://127.0.0.1:8000`.

- Swagger UI: `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`

## Запуск через Docker

```bash
docker compose up --build
```

После запуска API будет доступно на `http://127.0.0.1:8000`. SQLite-файл хранится в локальной папке `data/`.

## Тесты

```bash
python -m pytest -vv
```

## Основные эндпоинты

| Метод | Путь | Описание |
| --- | --- | --- |
| `POST` | `/bookings` | Создать бронь |
| `GET` | `/bookings` | Получить список броней |
| `GET` | `/bookings?date=2026-08-20` | Получить брони на дату |
| `GET` | `/bookings/{id}` | Получить бронь по id |
| `DELETE` | `/bookings/{id}` | Отменить бронь |

Пример запроса:

```json
{
  "name": "Анна Иванова",
  "phone": "+79991234567",
  "booking_date": "2026-09-20",
  "booking_time": "19:00:00",
  "guests": 4
}
```

## Принятые решения

Для хранения данных выбран **SQLite с асинхронным SQLAlchemy 2.0**, что позволяет сохранить простую конфигурацию проекта и при этом использовать полноценный ORM и асинхронную работу с БД. Код разделён на слои **API, схемы, сервисы и модели**, чтобы отделить обработку HTTP-запросов от бизнес-логики и работы с данными. Валидация входных данных вынесена в **Pydantic-схемы**, включая проверку имени, телефона, даты, времени и количества гостей, а бизнес-правила реализованы в сервисном слое. Для отмены используется **мягкое удаление** запись сохраняется в базе со статусом `cancelled`, благодаря чему история бронирований не теряется. Для тестирования используются `pytest` и `httpx.AsyncClient` с отдельной SQLite in-memory базой, что позволяет проверять API без зависимости от рабочей базы данных.
